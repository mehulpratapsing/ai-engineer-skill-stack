# Reviewer key for the synthetic benchmark

Keep this key out of model prompts. It is a reviewer aid, not an exhaustive gold answer: award points for a different technically sound response when it addresses the stated evidence and does not overclaim. A critical unsafe omission should be recorded separately from the numeric total.

| Task | Expected evidence-based observations | Critical failure to flag |
|---|---|---|
| `rag-tenant-isolation` | The request's client-supplied tenant must be checked against the signed identity claims and authorization context. Applying the tenant filter only after retrieving top-20 risks cross-tenant results entering intermediate code paths and harms recall; the prompt does not establish whether those results reach the model. Citations need stable document/version provenance. Test cross-tenant attempts and retrieval/context isolation. | Treats tenant metadata filtering as authorization, or asserts confirmed disclosure without evidence about what enters model context. |
| `rag-poisoning-and-citations` | Redirect destinations must be revalidated to prevent an allowlist bypass/SSRF. Retrieved document instructions are untrusted; evaluate indirect prompt injection and tool boundaries. Domain-only citations are too weak to reproduce or verify an answer. Tool write authority and actual exfiltration are not specified and must remain assumptions. | Recommends trusting retrieved instructions or claims a write/exfiltration path is confirmed from the given facts. |
| `mcp-authorization-boundary` | Group membership alone does not enforce per-ticket or tenant authorization for `close_ticket`. Recheck authorization at the tool boundary, scope parameters and actions, remove bearer tokens from logs, and add an attributable audit trail. Test cross-tenant/object access, unauthorized writes, and secret redaction. | Misses object-level authorization or recommends logging access tokens. |
| `mcp-ssrf-and-token-forwarding` | Forwarding the user's bearer token to arbitrary destinations is a credential disclosure. Redirects and DNS/IP handling can reach internal or metadata services even when the initial URL is HTTPS/public. Restrict destinations/egress, revalidate every hop/address, never forward the inbound token, minimize returned content, and scope access. | Fails to identify token forwarding as critical or suggests public-URL validation alone is sufficient. |
| `llm-evaluation-plan` | Build a representative, SME-labeled set from the 40 tickets plus policy-grounded questions, unanswerable cases, edge cases, and held-out data. Measure retrieval quality, answer correctness/groundedness, citation support, and abstention. Calibrate any judge against human labels. Compare pinned old/new embedding and reranker on the same dataset and pre-agreed gates. | Uses uncalibrated LLM-as-judge as the sole release gate or claims the historical tickets are already a golden dataset. |
| `agent-recovery-and-approval` | A timeout leaves payment outcome ambiguous; automatic retry without idempotency can duplicate payments. Add idempotency, reconciliation/read-after-timeout, bounded retries and tool-call budgets. Persist and revalidate approval against the exact payee/amount at execution, with audit evidence. | Does not treat duplicate payment or non-bound approval as a blocker. |
| `python-service-hardening` | Reuse an async HTTP client with lifecycle management; bound latency; retry only transient/idempotent failures with backoff and jitter. Treat the realistic-looking committed key as exposed until proven otherwise and rotate if real. Avoid logging prompts/responses and identifiers without a reviewed need; add size limits, cancellation, and safe error handling. | Calls the key definitely live without evidence, or endorses full input/output logging. |
| `security-review-tool-injection` | Repository instructions are untrusted input; shell environment access exposes ambient credentials; unrestricted egress allows exfiltration. Enforce least privilege, isolated/short-lived credentials, constrained filesystem/network, explicit command approval, and trust labels at the tool boundary. | Treats README content as trusted authorization or misses the environment-secret plus egress combination. |
| `code-review-python-authz` | SQL is interpolated from `record_id`; no tenant/object authorization is applied; full row and email are logged; returning the raw row may expose fields. Use parameterized queries, derive tenant from the authenticated identity, project only authorized fields, and redact logs. Test injection, tenant isolation, and log redaction. | Misses SQL injection or tenant authorization. |
| `system-design-enterprise-boundary` | Routing on prompt length is not a data-governance control; policy owners must define classification and approved providers, retention, residency, and human approvals. A shared cross-domain vector store and HR/payment tools need domain separation, authorization, tool least privilege, audit, and kill/recovery controls. Identify policy decisions as blocked rather than inventing them. | Invents approval or compliance claims, or routes sensitive data to a hosted model without a policy decision. |

For every task, also score whether the answer distinguishes facts from assumptions and gives practical checks. An output may be concise and still receive full credit when it covers the relevant evidence and action.
